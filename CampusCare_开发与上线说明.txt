CampusCare 系统开发与部署说明

一、项目概述
CampusCare 是一套面向校园维修业务场景的报修管理系统，覆盖报修提交、工单分配、维修跟进、消息通知、图片上传、沟通记录与服务评价等核心流程。

系统采用移动端与服务端分离的架构设计，由以下两部分组成：
1. Android 移动端应用：负责用户交互、业务操作与数据展示。
2. 后端服务系统：负责业务处理、权限控制、数据存储、文件管理与接口输出。

当前项目目录结构如下：
1. Android 客户端：D:\CampusCare\CampusCare
2. Java 后端服务：D:\CampusCare\campus-care-backend

二、系统技术架构
本项目采用典型的前后端分离架构，移动端通过 HTTP API 与服务端通信，服务端再与 MySQL 数据库进行数据交互。

整体架构如下：
1. 前端层：Android App
2. 接口层：Spring Boot REST API
3. 业务层：Service 业务逻辑处理
4. 数据层：JPA Repository
5. 存储层：MySQL 数据库 + 服务器本地上传目录

三、开发技术栈
1. 客户端技术栈
- 开发语言：Java
- 开发平台：Android 原生应用
- 界面实现：XML Layout + Activity + ViewBinding
- 构建工具：Gradle
- 主要依赖：
  AndroidX AppCompat
  Material Design
  ConstraintLayout
  RecyclerView
  CardView
  Glide
  Retrofit
  Gson
  OkHttp

2. 服务端技术栈
- 开发语言：Java 17
- 开发框架：Spring Boot 3
- 构建工具：Maven
- 主要组件：
  Spring Web
  Spring Data JPA
  Spring Validation
  Spring Mail
  springdoc OpenAPI / Swagger UI

3. 数据库技术
- 数据库类型：MySQL
- ORM 框架：JPA / Hibernate
- 表结构维护方式：根据实体模型自动同步更新

四、前端实现说明
Android 客户端采用原生开发方式，主要面向多角色业务使用场景，包括普通报修用户、维修技术人员与管理员。

客户端核心页面包括：
1. 登录与注册
2. 用户首页
3. 报修提交
4. 报修记录查询
5. 工单详情与维修进度跟踪
6. 消息通知
7. 工单沟通聊天
8. 技术员工单处理页面
9. 管理员工作台

前端通过 Retrofit 封装 API 调用，通过 OkHttp 处理网络连接，通过 Gson 完成 JSON 数据转换。界面层采用 XML 布局文件，业务交互逻辑由各 Activity 负责组织。

五、后端实现说明
后端服务采用 Spring Boot 构建，按照标准分层结构组织代码，具备良好的可维护性与扩展性。

主要代码结构包括：
1. Controller：对外提供 REST 接口
2. Service：封装业务逻辑
3. Repository：负责数据库访问
4. Entity：定义数据库实体模型
5. DTO：定义前后端交互对象
6. Config：系统配置、跨域处理与初始化逻辑

后端已实现的核心业务模块包括：
1. 用户认证与登录
2. 用户注册与密码管理
3. 报修工单创建、查询、删除、分配、接单与状态更新
4. 消息通知管理
5. 工单聊天沟通
6. 图片上传
7. 健康检查接口
8. 管理员用户管理

六、数据库设计说明
系统使用 MySQL 作为主数据库，负责存储业务核心数据。当前实现已覆盖以下主要数据实体：
1. User：用户信息
2. RepairRequest：报修工单
3. Notification：通知记录
4. ChatMessage：聊天消息
5. AuthToken：登录令牌
6. PasswordResetToken：密码重置令牌

数据库连接由服务端统一管理，支持通过环境变量注入部署参数，包括：
1. MYSQLHOST
2. MYSQLPORT
3. MYSQLDATABASE 或 MYSQL_DATABASE
4. MYSQLUSER
5. MYSQLPASSWORD

后端启动后，JPA/Hibernate 会根据实体定义自动维护表结构，便于开发阶段与部署阶段保持一致。

七、系统接口与前后端通信方式
客户端与服务端通过 REST API 进行通信，主要接口包括：
1. 认证接口：登录、注册、密码找回、密码重置、密码修改
2. 工单接口：创建工单、查询工单、分配工单、处理工单、评价工单
3. 通知接口：查询通知、已读处理、删除通知
4. 聊天接口：读取消息、发送消息
5. 上传接口：图片上传
6. 健康检查接口：服务状态检测

认证方式使用请求头传递令牌，客户端在登录成功后保存令牌，并在后续业务请求中附带该令牌完成身份校验。

八、开发流程说明
本项目的开发过程采用先业务建模、再服务端实现、后客户端联调的推进方式，流程如下：

1. 需求梳理
明确校园维修场景下的核心流程，包括报修、接单、派单、进度更新、通知、沟通与评价。

2. 角色划分
定义系统内三类业务角色：
1. Requester：报修发起方
2. Technician：维修处理方
3. Admin：系统管理方

3. 数据建模
围绕用户、工单、通知、聊天、认证等模块建立数据库实体结构。

4. 服务端开发
基于 Spring Boot 实现接口、业务规则、数据库操作、异常处理与上传能力。

5. 客户端开发
基于 Android 原生技术实现页面结构、交互逻辑、接口接入与状态展示。

6. 联调测试
完成客户端与服务端对接，验证登录、工单流转、通知、聊天、上传等主要业务链路。

7. 部署验证
完成数据库配置、服务端部署、客户端连接配置与整体运行验证。

九、本地开发与运行流程
1. 数据库准备
安装并启动 MySQL，创建业务数据库：
CREATE DATABASE IF NOT EXISTS campus_care
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
2. 启动后端服务
进入目录：
D:\CampusCare\campus-care-backend
执行：
mvnw.cmd spring-boot:run
默认服务端口：
8080
健康检查地址：
http://localhost:8080/api/health
接口文档地址：
http://localhost:8080/swagger-ui/index.html
3. 启动 Android 客户端
进入 Android Studio 打开：
#:\CampusCare\CampusCare
连接模拟器或真机后运行 App。
如果客户端需要连接本地服务，可将服务地址设置为：
http://10.0.2.2:8080/
该地址适用于 Android 模拟器访问本机服务。
4. 部署后端服务
部署到云平台
可接入支持 Java/Spring Boot 的托管平台，例如 Railway云部署环境。平台完成构建后自动启动服务，并通过环境变量注入数据库配置。

5. 配置文件上传目录
系统上传文件保存在应用运行目录下的：
./uploads
部署时需要确保该目录存在，且应用运行用户具备读写权限。

6. 客户端切换到生产地址
后端服务部署完成后，客户端将 API 基础地址配置为生产环境域名或云服务地址，即可访问正式环境。

7. 打包客户端发布包
在 Android Studio 中生成：
1. Debug APK：用于内部测试
2. Release APK / AAB：用于正式交付或上架发布

CampusCare 采用 Android 客户端 + Spring Boot 服务端 + MySQL 数据库的标准分层架构。客户端负责业务操作与展示，服务端负责接口、权限、流程控制与数据持久化，数据库负责存储用户、工单、通知与消息等业务数据。系统支持本地开发部署，也支持部署到云平台或 Linux 服务器，具备后续扩展与维护基础。
